# 🟣 MCP 服务器与 AI 智能体

一条安全直接的桥梁，使各类人工智能模型能够直接在您的设备上读取与创建思维导图。

### ⚡ 便捷的一键连接

无需手动编辑繁琐的配置文件，您可以在程序内直接连接智能体：

1. 打开菜单 `🤖 人工智能` → `🔌 将MMCelt连接到我的AI...`。
2. MMCelt 会自动搜索设备上已安装的终端命令行助手（Claude Code、Codex CLI 与 Gemini CLI）。
3. 点击所需助手旁的**连接**按钮，即可大功告成!

如果以后安装了新的助手，只需再次打开该窗口：每次打开都会重新动态扫描。“已连接”状态确保智能体知道 MMCelt 的所在位置以及如何通过 `--mcp-server` 与其建立通信。

### ⚙️ 手动配置与内嵌服务

如需手动配置您的 MCP 客户端，请在其 JSON 配置文件中添加以下内容：
```json
{
  "mcpServers": {
    "mmcelt": {
      "command": "C:/path/to/mmcelt.exe",
      "args": ["--mcp-server"],
      "env": { "MMCELT_WORKSPACE": "C:/path/to/your/project" }
    }
  }
}
```

MMCelt 的 MCP 服务器**已内嵌在主执行文件内部**：无需配置任何外部运行环境或额外依赖。

### 🛡️ 全面安全防护：工作目录隔离与备份机制

数据安全是第一要务。当 AI 助手与 MMCelt 协同工作时，**严格限制其仅能在指定的项目工作目录中进行读写**。该边界由 `MMCELT_WORKSPACE` 环境变量严格限定。

任何试图越界访问其他文件夹的操作都将被立即拒绝。此外还提供多重安全保障：
- **自动备份机制：** 在智能体修改现有文件之前，MMCelt 会自动保存带有精确时间戳的备份文件（例如 `project.mmcelt.20260918-120000.bak`）。若对结果不满意，历史数据完好无损。
- **尊重原创成果：** AI 可以提议新的分支与关系，但**绝不会擅自删除或挪动**您亲手创建的节点。AI 提交的所有内容都会在界面上醒目标记为“AI 生成”，始终由您把关审批或修正。

### 🔨 MCP 服务器的 6 项官方工具

助手配有专门为协作打造的六项官方工具：

- `mmcelt_workspace_info`：查询当前已授权的工作目录及其中包含的 `.mmcelt` 导图。这是其首要调用的工具，以防虚构路径。
- `mmcelt_create_mindmap`：在磁盘上创建全新的 `.mmcelt` 思维导图。
- `mmcelt_read_mindmap`：读取导图层级、注释及待解决的疑虑。
- `mmcelt_sync_ai_progress`：实时拓展导图，新增带有角色、优先级与关联关系的节点。
- `mmcelt_get_human_feedback`：在触碰核心内容前主动读取您的人工修正与指导原则。
- `mmcelt_export_ai_markdown`：将导图转换为排版精美、结构严谨的 Markdown 概要。

### 🌱 如果导图由您亲手创建：对您著作权的完整尊重

智能体可以丰富您的导图，但永远不会取而代之。它可以补充节点、配置角色和标签，并在独立分支间建立交叉关联。
所有新加入的内容均会标注为 AI 生成，不能未经允许标记为您已批准，且绝不会重新激活被您标记为已放弃的分支路径。

### 🏷️ 拥有同名节点的处理机制

在决策类导图中，在不同分支下重复出现常见字词（如“是”、“否”或“待定”）十分普遍。若 AI 仅凭重复名称发起修改请求，MMCelt 会拒绝这一歧义操作，并返回所有匹配项的唯一标识符，要求其指明确切的目标节点。这样可以彻底消除误操作。

### 🧭 如果终端中没有安装任何助手该怎么办？

无需担忧：即便终端中未安装任何智能体，MMCelt 也同样具备完整的实用价值。您可以在网页浏览器中使用 ChatGPT、Claude.ai 或 Gemini 等服务，利用菜单中的 `🤖 人工智能` → `📋 复制供AI使用的主提示词...` 或 `💾 导出供AI使用的.md文件...` 导出需求。随后只需将 AI 的回复粘贴至 `🤖 人工智能` → `📥 从AI导入（ChatGPT、Claude、Gemini）...`，即可将文本即刻转化为图形节点。
