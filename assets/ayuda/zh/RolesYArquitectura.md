# 🏛️ 语义角色与导图架构

随着工程规模的扩大，充满完全相同方框的思维导图很容易让人难以分辨。为规避此问题，MMCelt 允许您为每个节点赋予明确的**语义或架构角色**。

角色定义了各个概念的内在性质及其在项目中的战略权重。借助这一机制，您与人工智能大模型均可瞬间分辨出哪些是战略支柱、哪些是日常临时任务，哪些又是待决的开放疑问。

### 📋 检查器中提供的 6 种角色

在导图中选中任意节点时，您会在右侧面板 (检查器) 中看到**“角色”**下拉菜单。您可以从以下六项职能中进行选择:

1. **🎯 核心概念:**
   - 思维导图的根节点，整棵树形结构的源头。
   - 代表您正在打造的产品、企业、研究课题或应用程序。一幅导图中有且仅有一个核心概念。

2. **🏛️ 战略支柱:**
   - 支撑整座大厦的关键核心主干支柱。
   - 在软件工程中通常对应各主要层次 (如前端、后端、数据库或安全模块)；在商业规划中可对应市场、销售、财务或运营部门。

3. **📌 子主题 / 模块:**
   - 隶属于特定战略支柱的具体业务组件或二级领域。
   - 例如在*后端*支柱下，子主题可以细分为*认证服务*、*支付网关*或*消息通知中心*。

4. **❓ 假设 / 疑问:**
   - 开放式探索问题、架构选型分歧或技术可行性尚待求证的实验点。
   - 例如: *“即时通信功能应当采用 WebSockets 还是 Server-Sent Events?”*。

5. **⚡ 任务 / 执行项:**
   - 具备明确验收标准与交付物的具体可执行行动步骤。
   - 例如: *“设计用户登录页面”* 或 *“编写订单计价模块的单元测试用例”*。

6. **🔧 资源 / 工具:**
   - 项目所必需的第三方类库、系统依赖项、参考技术文档、外部 API 或辅助效能工具。

### 💡 如何变更角色及其对导图与 AI 的深远影响

如需更改节点的角色，请先选中该节点，并在右侧属性检查器的**“角色”**下拉菜单中指定所需选项。

**🎨 画布上的视觉辨识度:**
每种角色都在图形画布上为节点赋予鲜明的视觉特征:
- 专属辨识图标与边框轮廓，助您轻松统览全局。
- 清晰的连接线条直观呈现项目内在的有机脉络。

**🤖 为什么 AI 高度重视角色划分?**
当您将导图导出或发送至 AI 智能体 (如 Claude Code、Codex CLI 或 Gemini CLI) 时，大模型接收到的绝非平铺直叙的文本碎屑:
- **洞悉系统顶层架构:** 明确知晓*战略支柱*关乎顶层一致性，绝不可随意删改或颠覆。
- **严格区分疑问与定论:** 将*假设 / 疑问*视作开放课题，主动针对其提供技术利弊权衡与备选方案。
- **产出高度协调的任务:** 在要求其细化某一模块时，AI 会精准规划具体的*任务 / 执行项*，并推荐配套的*资源 / 工具*以落实交付。
