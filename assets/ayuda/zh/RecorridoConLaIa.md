# 🤖 与 AI 协作的完整全景流程

其他各个主题分别讲解了系统的各个独立模块。本篇则旨在呈现**完整的协作旅程**:
究竟什么样的数据会离开您的计算机、其背后的设计原理、您拥有哪些决定权，
以及当人工智能返回响应时它究竟被允许做些什么。

如果您只打算阅读一篇关于 AI 协同的主题，请务必阅读本篇。

### 🗺️ 四步协作旅程

**1. 您构建并完善思维导图。** 在此阶段您所做的任何操作都不会对外发送。
您可以自由搭建分支骨架、撰写长篇备注、标记任务状态与技术疑点、
梳理跨分支交叉依赖，并详实充实项目愿景。
脑海中写在导图上的信息越完整，AI 需要胡乱推测的内容就越少。

**2. 应用程序装配上下文文档。** MMCelt 绝不会直接发送您的底层 `.mmcelt` 存储文件。
对于一次全自动会话，系统严格按固定顺序组装四个模块:
MMCelt 核心契约、项目通用规则、导图完整上下文以及单个当次任务。
整张导图作为真实上下文完整随附，绝非残缺的粗略摘要。

**3. 您亲自阅读并确认批准。** 这是最少被初学者重视、却提供最坚实保护的关键屏障。
在任何数据发送出去之前，您都能在屏幕上审阅完整文本，
并有权直接修改其中两个模块的内容。

**4. AI 将工作成果回填至导图。** AI 绝不能直接修改您的本地文件，
而是必须通过受规则严密约束的六项专用工具进行交互。
AI 提交的所有节点在诞生之初均被打上 AI 生成的专属印记，
是否将其核准采纳完全由您一人决断。

### 📤 两种导出交互路径

| | 交互方式 | 最佳适用场景 |
|---|---|---|
| **手动模式** | `📁 文件` → `🤖 导出面向 AI 的 Markdown (.md)`，并将文件上传至对话界面 | 支持任何大语言模型，包括纯网页端产品。无需在本机安装任何命令行组件 |
| **自动模式** | `🤖 人工智能` → `📤 发送到...` 并选定目标终端智能体 | 适合已在本地配置好命令行智能体并期望导图静默自动更新的深度开发者 |

如果您采用手动交互方式，可在获取回复后通过
`📥 从AI导入（ChatGPT、Claude、Gemini）...` 导入结果;
若采用自动模式，导图将在后台自动捕获响应并就地刷新。

### ✍️ 您能在何处做出何种关键决策

- **阐明全局总体构想:** `🤖 人工智能` → `🧭 项目与 AI 指令` → **项目** 标签页。
- **裁决成果是否符合预期:** 将节点明确标记为 `🛡️ 人工已核准` 或
  `⚠️ 需修正`，并通过
  `🤖 人工智能` → `🛑 向AI发送修正意见与指令...` 统一派发。
- **发送前全面核验:** 点击 `🤖 人工智能` → `👁️ 预览AI Markdown (.md)...`，
  可在指令真正注入终端或贴入对话框前，在屏幕上逐字逐句审阅生成的确定文本。
- **明确当次重点委托:** 在派发预览面板中直接编辑“当次会话委托”区块。
- **固化长期行为规范:** 在同一预览面板中统一维护项目通用行为守则。

在正式派发前，您也可以在 **`🧭 项目与 AI 指令`** 面板中提前布置一切。
**指令** 标签页支持挑选 **AI 文档语言**、固化通用规则，
并逐项审查检测到的本地原生指令源文件。**任务模板** 标签页可一键注入
专项提示词配方，而 **完整预览** 则呈现即将送出的最终全量字符串。

本地原生提示词文件绝不会仅仅因为存在于磁盘上就被强行卷入。
它们首先会以 **新来源** 状态醒目呈现; 只有在点击 **接受此版本** 后，
才会在其文件字节未发生改变的前提下保持预选状态。一旦外部内容发生篡改，
勾选将自动失效并在当前版本旁对比显示历史版本。
您可通过复选框完全自主决断某项配置是否最终生效。

当多项规则出现冲突时，输出文档自身已内置了自顶向下的权力约束层级:
**您在导图上手动标记的修正指令** 享有最高权威，
其次为 MMCelt 平台协议规范，再其次为项目规则，最后才是当次任务委托。

### 🔙 AI 响应回传时的权限边界

**AI 被明确允许:** 读取思维导图全文、读取您下达的纠错批注、
新增衍生节点并回传进展报告，以及建立全新导图。
其权限被严格限定于这六项标准化工具之内，绝无越权可能。

**AI 严禁执行的操作:** 严禁私自覆写您的原始 `.mmcelt` 二进制或文本档案、
严禁越界访问未获您明示授权的外部工作区路径，
更**绝对无权擅自宣称某项内容已被您核准**。
所有由其递交的内容必须被强制打上 AI 标记，核准权永远牢牢掌控在您手中。

此外系统提供了严密的审计追踪: 您所批准的精准提示词文本均归档于 `.mmcelt/sesiones`，
如果自动化改动被回填至您刚刚手动编辑过的导图上，系统会预先自动落盘 `.bak` 备份副本。

确认对话框绝非毫无实质的装饰性弹窗。在正式启动终端前的最后一刻，
MMCelt 会对导图数据、规则定义及源文件执行即时二次哈希校验。
一旦察觉任何外部修改痕迹，系统将判定先前确认已作废，
主动拒绝启动智能体并要求您重新核对变更。

### ⚠️ 本套机制的安全边界澄清

向 AI 发送的文档开篇即明示，思维导图内所承载的全部文字属于**纯数据，而非系统指令**。
该声明大幅减少了 AI 的理解偏差，但这**并不等同于绝对的沙箱安全隔离**:
外部导入的标题或备忘录依然可能暗藏诱导性提示词注入代码。

真正行之有效的防护壁垒建立在底层体系之上:
严密受限的工作目录访问白名单、功能极简且受控的六大工具集，
以及您在数据离机前亲自把关预览的严谨工作习惯。
这也是为什么我们始终建议您至少通读一次完整预览。

**💡 如果您的终端尚未安装命令行智能体该怎么办?**
如果在进入 `🤖 人工智能` → `📤 发送到...` 时看到“未检测到已安装智能体”的提示，
请完全不必担忧: **您无需配置复杂的开发终端或前沿智能体，也能流畅使用 MMCelt 的 AI 赋能**。

您完全可以依托日常使用的标准网页浏览器轻松开展工作:
1. 点击 `📁 文件` → `🤖 导出面向 AI 的 Markdown (.md)`（或先通过 `🤖 人工智能` → `👁️ 预览AI Markdown (.md)...` 审查文本）。
2. 在浏览器中打开您常用的任意 AI 对话服务（ChatGPT、Claude、Gemini 等）。
3. 粘贴导出的 Markdown 内容，并附上您对推演导图的具体要求与设想。
4. 当 AI 回复包含 JSON 结构块或格式化 Markdown 文本时，将其一键复制。
5. 返回 MMCelt 界面，点击 `🤖 人工智能` → `📥 从AI导入（ChatGPT、Claude、Gemini）...` 并粘贴回复。新增的分支树将立即呈现在画布上。

若您未来在操作系统终端中配置了 CLI 命令行智能体（例如 Claude Code、Codex CLI 或 Gemini CLI），
MMCelt 会在检测到其存在于系统环境变量 PATH 后自动识别并支持一键唤起。
