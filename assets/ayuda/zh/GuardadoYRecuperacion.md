# 💾 存盘与灾难恢复机制

### 💾 手动保存 (Ctrl + S)
将导图保存至您指定的路径。若发生任何写入异常（权限不足、磁盘存满、云盘未同步），**软件会立即弹窗报错**。系统绝不会在未完成实际写入校验前误报保存成功。

在弹出的文件夹选择框中，软件会自动定位至最相关的目录：即当前文件所在路径，或者 **导图节点所关联的代码项目目录**。

### 🛟 自动灾难恢复备份
每隔两分钟，若导图发生实质改动，系统将在后台自动写入一份安全副本。若程序发生异常中断，下次启动时软件会自动提示您恢复工作进度。

该间隔**可以调整，也可以完全关闭**，位于 `🎨 视图与设计 → 💾 自动保存`：关闭、每分钟、每两分钟、每五分钟或每十分钟。所选设置会在会话之间保留。

**自动备份不能替代主动保存。** 它是兜底安全网，而非永久存档。请依然养成按下 Ctrl + S 的良好习惯。

恢复副本存放于 MMCelt 应用数据目录中（Windows 环境下为 `%APPDATA%\MMCelt\recuperacion\`），**绝不会污染您的代码仓库目录**。系统仅保留最近一次会话的副本，并在您执行正式手动保存后自动清理。

在自动排版模式下，单纯拖拽节点不会触发脏标记：排版引擎后续仍会重新排列，从而避免浏览时的无意义磁盘写操作。

而在 **自由手动拖拽模式** 下，移动节点会被视作实质修改，因为手动布局凝聚了您的劳动成果。

### ⚠️ 启动时弹出恢复提示的处理
弹窗会明确展示副本生成时间及包含的导图名称。您可以自由抉择：若是此前主动放弃保存而退出，直接丢弃即可。系统绝不会未经确认强制静默覆盖。

### 🛡️ 损坏文件的安全防护
若导入的文件包含非法数据结构（如拓扑闭环、缺失根节点、引用断裂），MMCelt 会在解析时主动拒绝加载并指出问题节点。这并非武断限制：强制加载会导致程序陷入死循环崩溃。若该文件由 AI 生成，请让其重新输出；若存在同名 `.bak` 备份文件，可尝试打开备份。

### 🌐 开放互操作格式（OPML 与 FreeMind .mm）
除了原生 `.mmcelt` 格式外，您还可以通过两种开放且非专有的标准格式导出和导入思维导图：OPML（分层大纲）与 `.mm`（FreeMind 及 Freeplane）。

导出为 OPML 或 `.mm` 时，节点标题、分支层级以及文本备注均保存在标准格式标签中，可供任何第三方大纲或思维导图工具直接查看。MMCelt 专有但传统格式无法原生承载的字段（进度状态、优先级、架构角色、人工审核状态、代码路径及横向交叉连接），均以结构化 JSON 的形式序列化保存在每条备注末尾。

将此类文件重新导入 MMCelt 时，所有元数据与横向连接均可 100% 精确还原，不丢失任何细节。若在其他软件中打开，用户依然可以查看完整的大纲结构，并在备注栏中读取这些元数据文本。

当导入由其他软件生成且不含 MMCelt 元数据的外部文件时，程序将自动赋予安全的默认值（构思状态、中优先级、除根节点获得"核心概念"角色外其余节点统一为"子主题"角色），自动应用均衡的分支空间排布算法以防止所有节点重叠在中心，并弹出清晰的提示对话框，说明哪些属性已按默认规则初始化。
