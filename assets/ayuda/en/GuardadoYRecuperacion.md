# 💾 Saving and Recovery

### 💾 Manual Save (Ctrl + S)
Saves wherever you choose. If anything fails — permissions, full disk, unsynced cloud folder — **the application informs you immediately**. It never reports a successful save without verification.

When selecting a folder, the file dialog opens at the most probable location: current file directory, or **the code project directory referenced by nodes** if file paths are set.

### 🛟 Automatic Backup
Every two minutes, if the map has changed, a recovery backup is written. If the program closes unexpectedly, on restart you will be prompted to recover it.

That interval **can be changed, or turned off entirely**, under `🎨 View and Design → 💾 Autosave`: off, every minute, every two, every five or every ten. The choice is remembered between sessions.

**Auto-backup does not replace saving.** It is a safety net, not persistent storage. Continue pressing Ctrl + S.

Backups are stored in MMCelt app data folder (`%APPDATA%\MMCelt\recuperacion\` on Windows), **never inside your project workspace**: preventing clutter in your repositories. Only the latest session is kept, and it is cleared once you perform a manual save.

In automatic layout modes, dragging a node does not trigger a dirty state: the engine will reposition it anyway, avoiding unnecessary disk writes while browsing.

In **Manual Free Position**, dragging does count as a change, because custom node layout is your deliberate work.

### ⚠️ When offered recovery on startup
The dialog displays backup timestamp and map title. You decide: if you exited deliberately without saving, discard it. It is never restored automatically.

### 🛡️ Corrupted Files
A file containing an impossible structure — cyclic loops, missing root node, broken references — is rejected on opening with the offending node highlighted. This is a safety measure: loading it would freeze the application. If generated by an AI, request a re-generation; if a `.bak` copy exists alongside, try opening it.

### 🌐 Open Interchange Formats (OPML and FreeMind .mm)
In addition to the native `.mmcelt` format, you can export and import mind maps in two open non-proprietary standards: OPML (hierarchical outlines) and `.mm` (FreeMind and Freeplane).

When exporting to OPML or `.mm`, node titles, tree hierarchy, and freeform text notes are saved in standard XML tags readable by any third-party outline or mind map viewer. MMCelt-specific attributes not natively supported by these classic formats (status, priority, role, human review, source code paths, and lateral connections) are serialized as structured JSON at the end of each note.

Re-importing that file into MMCelt fully reconstructs the map with 100% fidelity, restoring every metadata field and lateral cross-connection. When opened in another tool, you will see the full mind map outline and can read the metadata as informative text inside the note.

When importing an external file created in another application without MMCelt metadata, the software assigns safe default attributes (Idea status, Medium priority, Subtopic role for every node except the root, which becomes Central Idea), automatically applies a balanced visual layout so that nodes are not piled up in the center, and displays an explicit informative notice explaining which fields have been initialized.
